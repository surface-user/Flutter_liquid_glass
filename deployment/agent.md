# deployment 修改与验证入口

适用：`deployment/` 内的实验台、独立部署目录、诊断、测试及产物。按用户要求使用此文件名；开始任务时必须显式读取本文件，不能假定所有工具都会自动发现小写 `agent.md`。

## 开始前

1. 依次阅读根 `AGENTS.md`、`../doc/AGENTS.md`、`../doc/task.md`。
2. 阅读开发参考手册：[玻璃组件实验台参考手册](../doc/component-lab-reference.md)。组件职责、可修改参数、合法插槽、已知问题和逐项验证以该手册为核对清单。
3. 查看外层仓库和相关 deployment 独立仓库的 `git status --short`；保留用户数据、现有失败日志与截图。
4. 明确本轮授权：用户已审阅并批准按参考手册修复宽高、类型切换和无效参数，完成逐组件交互及中文排版验证后更新原站点。所有代码改动仍限于 deployment。后续未授权的新范围不得借此扩大。

## 修改边界

- 应用代码、组件库快照、配置、测试、日志、截图、下载包及构建产物均只放在 `deployment/`。
- `../doc/component-lab-reference.md` 是用户明确批准的文档例外；不要顺带修改外层 `lib/`、`test/`、`example/`、依赖、工作流或其他文档。
- 不清空用户 localStorage/布局或删除历史失败产物来让检查通过。需迁移数据时必须保留旧数据/导出途径。
- 不改变现有 Sites 项目 ID、受众或创建重复项目。主组件库和 Sites 独立源码仓库分别处理，避免污染外层仓库。

## 获准实现后必须逐项验证

1. 修改前按参考手册 C01–C22 和 LAB-01–LAB-13 确认受影响组件、调用方、参数、嵌套槽、测试与旧布局；先给缺陷建立可观察的复现。
2. 类型切换按“组件 + 参数路径”适配，不能只改 type；菜单项、目标弹窗、目标页面、图标、文字、样式和渐变分别定义合法结构。更新参数面板、校验、默认模板、中文说明和运行资源生命周期。
3. 尺寸区分外框 w/h、内部 width/height、约束、字号和行高。必须通过实际尺寸与可见布局证明生效，不以保存值变化代替。
4. 每项可编辑参数写清楚触发条件和预期效果；不支持项移除或明确禁用说明，不保留无效的假参数。
5. 保留减少动画、系统无障碍、性能降级、公开 API/旧布局兼容、背景分组隔离和视觉回归要求。
6. 运行参考手册第 9 节中与改动相关的逐项矩阵；至少完整实验台测试、格式、分析。涉及 Web 则运行 `component-lab-site/build.ps1`；Flutter 命令串行。
7. 检查中文长标签、深层属性、所有下拉和浮层；覆盖 320/390/820/1180/1500 宽度、字体缩放和画布缩放。保存并实际查看截图，验证真实命中，不能用自动更新图像基准掩盖错版。
8. 诊断测试目前断言现有缺陷；修复时改为审阅后的正确契约，纳入稳定回归，保留原失败证据。
9. 把每个组件/参数的结果、命令、日志、截图和未验限制记录到手册或 deployment 验证记录；不得把默认挂载、总测试数或旧提交结果冒充全部交互验收。

## 交付

先完成本轮授权的具体范围。发布前按 Sites 技能同步精确源码、构建/打包、保存版本、部署并确认结果，权限保持原样；文档待审阅或用户要求不发布时不执行。报告实际修改、验证、未修复问题和真机/物理 IME/浏览器边界，不能虚报已全测或已修复。
