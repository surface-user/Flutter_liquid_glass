# Liquid Glass 与 M3E Canvas：组件定位、动效与使用流程差距分析

日期：2026-11-14。用途：供用户审阅后安排源组件库接口和实验台更新。**本文是分析与建议，不表示这些改造已经实现或获得实施批准。**

## 1. 结论与核验范围

目前最需要解决的是：实验台把“用户要放置的界面元素”“元素如何排列”“点击后执行什么”“底层如何绘制”放在相近的入口中。参数合法、能成功渲染之后，用户仍然需要先理解 Flutter 组件树，才能完成“点击查看一段说明”这样的简单任务。

M3E Canvas 更完整的部分在于：按用途找组件、根据当前对象显示属性、将外观与触发分开、用屏幕和连接表达流程、在独立预览中试走、最后交付工程或说明。它也有只展示外观的输入框、选择器和弹层，不能把它的组件数量直接当成真实功能数量。

建议实施顺序：**先整理现有能力的入口和编辑方式，再补工程流程，最后按真实场景补库接口。** 弹窗的标题、正文、操作按钮、打开与返回已有基础接口，第一轮精简不依赖新增弹窗 API。

## 2. 为什么截图中的弹窗显得冗杂

### 2.1 一个操作被拆成了用户不熟悉的代码层次

当前“打开玻璃弹窗”模块实际执行的是：外部按钮 → 打开动作 → 弹窗容器 → 标题/正文/操作按钮。属性面板却沿底层对象展示“内容组件”“目标内容”“组件类型”，用户必须自己判断正在修改哪一层。

| 截图中的内容 | 在当前本地实现中的意义 | 用户更需要看到的内容 |
| --- | --- | --- |
| 外层模块的“内容组件” | 打开弹窗那个按钮内部的 `child`，不是弹窗正文 | “触发入口：按钮”“入口文字：查看说明” |
| “目标内容” | 打开后由 `builder` 创建的弹窗对象 | “弹窗内容”，直接编辑标题、正文和按钮 |
| 目标里的“组件类型：玻璃弹窗” | `builder.type=GlassDialog` | 普通模式固定为弹窗，省去无意义的单选项 |
| 标题中的“组件类型：文字” | 标题槽放了一个 Text 节点 | 直接给“标题文字”；需要图文标题时再选择模板 |
| 正文中的“组件类型” | 要构建正文子树 | “文字说明 / 图文内容 / 输入表单 / 自定义内容”，按用途选 |
| 同页出现画布宽高和弹窗约束 | 一个控制编辑模块外框，一个控制打开后的窗口 | 分为“编辑器中的位置”和“弹窗大小”，后者优先显示 |

这不是把所有公开函数自动反射出来的列表。实验台手工注册22种类型；其中包含 UI 控件、SDK 基础节点、主题/分组包装器，以及函数和路由的演示适配。它们缺少面向任务的统一分类，所以看起来像把所有接口都塞进了一个下拉框。〔F01、W01—W03〕

### 2.2 截图与当前本地修复要分开判断

当前本地 `slotTypes` 已将弹窗目标限制为 GlassDialog，触发器/标题限制为 Text、Icon、Row、Column；并非每个插槽仍能选全部22项。第二张图的完整类型列表，不能仅凭截图确定属于哪个参数路径或哪一个构建版本。

但当前 `contentTypes` 仍允许17种内容节点，包括 GlassSurface、AnimatedGlassSurface、GlassGroup、LiquidGlassTheme。根类型选择也仍列出全部注册项。**上一轮解决的是结构和类型是否合法，本轮需要进一步解决用户是否理解这些选项、是否需要看到这些选项。** 只把候选从22项减到17项，仍没有完成产品分类。〔W02〕

### 2.3 先问清“显示文字”是哪一种交互

| 用户想完成的事 | 合适的界面形式 | 现有基础与差距 |
| --- | --- | --- |
| 在页面上一直显示一段说明 | 普通文字/标签 | Text 已支持；不需要弹窗 |
| 点击按钮或图标，阅读说明并关闭 | 模态说明弹窗 | GlassButton/GlassIconButton + showGlassDialog + GlassDialog 已支持；W |
| 点击一段文字，打开说明 | 文字链接式触发入口 + 模态弹窗 | Text 本身没有点击回调；可用 SDK TextButton/点击包装接入，W+S，无需为此新增“文字弹窗函数” |
| 鼠标悬停或键盘聚焦时看一句提示 | Tooltip 式轻提示 | 图标按钮已有 tooltip；通用文字提示可用 SDK 组合，但实验台没有对应通用入口，W+S；不应强迫用户创建模态弹窗 |
| 点击信息图标，在旁边看一张可交互小面板 | 锚定浮层/Popover | 当前没有专门 GlassPopover 契约；SDK 浮层可组合，若要求统一玻璃外观、定位和关闭行为，再作为 L 候选 |
| 填写内容，确认后取得结果 | 表单弹窗 | 标题/正文/按钮与返回值已有；表单字段编排、校验和结果映射在网站不足；部分输入参数另有 L 缺口 |

Tooltip、菜单、模态弹窗、页面跳转分别有不同的遮挡、焦点和关闭语义。不能把它们统一成“弹出东西”，再让用户从容器类型中猜出实现。

## 3. 重新划清组件功能定位

### 3.1 三个容易混淆的名称

**玻璃卡片 GlassCard：** 用户能理解的内容块，可装文字、图片或按钮；可选整卡点击。当前库没有内置 title/subtitle/image 字段，内容通过 `child` 组合。网站可以提供这些常用内容模板，把它们映射到已有 child；无需先给库新增一套重复的卡片 API。注意：库的 onTap 默认为空，实验台默认模板却设为 log，导致普通卡片一开始就表现为可点击；建议普通卡片默认静态，把“整卡可点击”作为显式选项。〔F02、W01〕

**玻璃表面 GlassSurface：** 给任意内容提供玻璃材质、裁剪、内外边距和尺寸约束的底层容器，不自带点击语义。适合开发者自定义外观，不应作为“弹窗正文要显示什么”的常用答案。普通模式可把它表述为“容器的玻璃外观”；开发模式保留原类型。〔F02〕

**局部主题 LiquidGlassTheme：** 给一段子树覆盖颜色、密度、间距或动效规则。它不是一块独立内容，当前预览中出现的按钮来自其默认 child，不代表主题本身是一种按钮。应进入“此区域的外观覆盖/恢复继承”，高级模式才展示包装节点。〔F05、W01〕

同样，“玻璃分组 GlassGroup”指背景过滤合组/隔离，不是把画布中多个元素编组拖动。把它留在基础组件菜单中，容易让用户建立错误预期。〔F03〕

### 3.2 当前22种注册项逐项归位

这是对现有能力的入口建议，不要求逐项新增公开类。普通模式保留常用任务入口，高级模式保留开发者需要的结构表达。

| 当前注册项 | 实际职责 | 推荐的普通入口 | 高级能力与边界 |
| --- | --- | --- | --- |
| Text | 显示文字 | 内容 → 文字/标签 | 字体、行高、溢出；文字不自动获得点击动作 |
| Icon | 显示装饰图标 | 内容 → 图标 | 点击应选择图标按钮或显式触发包装 |
| GlassButton | 触发一个操作 | 操作 → 按钮 | 文字/图标组合、禁用、状态样式、动作 |
| GlassIconButton | 只有图标的操作 | 操作 → 图标按钮 | 可访问名称、提示文字与图标分开 |
| GlassTextField | 真正的单行文字输入 | 输入 → 文本输入 | 搜索是输入用途；不会自动执行数据查询 |
| GlassCard | 信息容器，可选整卡操作 | 容器 → 卡片 | 常用标题/正文/操作模板；自定义子树进高级模式 |
| GlassMenu | 触发器加单层操作菜单 | 操作 → 菜单 | 每项独立文字、图标、禁用和动作；不是任意信息浮层 |
| MenuItemButton | 菜单内部一个操作项 | 菜单内部“添加菜单项” | 不作为默认独立画布材料 |
| GlassDialog | 标题、正文、操作区的弹窗容器 | 反馈 → 弹窗的内容设计 | 在画布上是嵌入预览；模态打开通过动作完成 |
| showGlassDialog | 打开弹窗并返回结果的函数 | 动作 → 打开弹窗/“试用弹窗” | 保留开发调用演示；与 GlassDialog 合并为一个普通设计入口 |
| GlassPageRoute | Flutter 页面转场路由 | 动作 → 前往页面 | 不作为普通可放置内容；没有自动生成多屏工程 |
| GlassNavigationItem | 单个受控导航条目 | 导航 → 导航项 | 不等于整条导航栏，也没有页面管理器或资源树 |
| GlassTab | 单个受控标签与关闭回调 | 导航 → 标签项 | 标签集合、当前页和关闭规则属于调用方 |
| GlassToolbar | 一组可换行的操作项 | 导航/操作 → 工具栏 | 当前是 Wrap 布局，不自带全部编辑命令 |
| GlassAppBar | 页面顶部应用栏 | 页面结构 → 顶栏 | 需要页面布局插槽；散放画布不自动占据页面顶部 |
| Row | 横向子节点排列 | 布局 → 横排 | 当前适配给子项分配宽度；不是任意响应式栅格 |
| Column | 纵向子节点排列 | 布局 → 竖排 | 当前适配可滚动；与库原生布局 API 区分 |
| GlassBackdrop | 渐变/光斑背景，可选动画 | 页面外观 → 背景 | 不放入常规弹窗正文候选；持续动画必须明确开启 |
| GlassSurface | 通用材质容器 | 外观 → 玻璃材质；高级 → 自定义表面 | 不自带内容语义或交互 |
| AnimatedGlassSurface | 材质变化时插值 | 外观 → 材质切换动效 | 不表示持续播放的动画，也不提供时间轴 |
| LiquidGlassTheme | 子树局部主题覆盖 | 外观 → 此区域的主题覆盖 | 合并/替换、继承来源进高级设置 |
| GlassGroup | 背景过滤优化与重叠隔离 | 高级 → 背景过滤策略 | 与编辑器编组完全不同，不承诺一起移动/对齐 |

左侧菜单建议按“内容、操作、输入、容器与反馈、页面结构、布局”组织；背景放页面设置，主题放外观，过滤策略放开发设置。首页可以只突出文字、按钮、图标按钮、输入框、卡片、菜单、弹窗这几种常见入口，避免用户第一次就面对全部构造类型。

源库有26个公开声明；实验台22种类型由17个库中名称和5个 SDK 节点组成。17个库中名称又包含13个面向内容/操作的 Widget、两个主题/分组包装器、一个路由类和一个打开函数。因此“接口数、注册类型数、普通用户组件数”应分别统计。〔F01、W01〕

### 3.3 普通属性面板与开发参数的边界

| 普通模式 | 高级模式 | 开发配置 |
| --- | --- | --- |
| 名称/文案、图标、内容条目、操作用途、尺寸方案、外观预设 | 自定义布局、详细间距、颜色/材质覆盖、状态样式、局部主题 | 原始节点类型、builder、controller/FocusNode 标识、路由设置、完整 JSON |
| 文字按钮入口直接填文案 | 需要图标+文字时编辑组合模板 | 可以直接看 SDK 节点与插槽 |
| 显示“当前对象：删除确认弹窗” | 面包屑定位“删除确认 / 正文 / 输入框” | 显示对应参数路径帮助排错 |

隐藏底层项只改变入口，不删除旧数据表达能力。高级用户仍能打开已有复杂布局；普通模式应提示存在高级内容，并允许显式切换查看，不能静默重置为简单模板。

## 4. 以弹窗为第一项改造范例

### 4.1 用途先于底层类型

建议进入“弹窗”后先选“文字说明、确认操作、输入信息、自定义内容”四种用途。用途负责填充初始内容和编辑表单，不强制改变旧的底层渲染协议。

| 用途 | 普通面板字段 | 动作 | 可观察的完成条件 |
| --- | --- | --- | --- |
| 文字说明 | 入口形式/文案，标题（可空），正文，关闭按钮文字，宽度方案 | 打开、关闭 | 改正文后直接在内容预览看到；运行时弹窗正文相同 |
| 确认操作 | 标题、说明、取消/确认文案、危险操作外观 | 取消返回空/约定取消值；确认返回约定结果 | 两个按钮的返回结果可区分，不假装已经删除业务数据 |
| 输入信息 | 标题、字段列表、初始值、提示/错误、确认/取消 | 修改临时草稿、校验、确认返回表单结果 | 取消不提交；校验失败保持草稿；确认结果可观察 |
| 自定义内容 | 内容结构树、布局、材质和各节点动作 | 复用已有动作 | 必须主动进入高级模式，结构与选中对象清楚 |

其中前两项可直接使用现有组件完成。第三项需要网站的表单状态与结果组装；若字段需要多行、密码等，还要补当前 GlassTextField 未透传的参数。用途预设不是后端业务实现。

### 4.2 推荐的编辑层次

```text
弹窗：删除确认
├─ 入口：按钮 / 图标按钮 / 文字链接 / 仅在动作中调用
│  └─ 文案、图标、提示
├─ 内容：标题、正文、操作按钮
├─ 行为：遮罩能否关闭、取消/确认的返回结果
├─ 外观：宽度方案、内边距、材质预设
├─ 动效：打开/关闭示意、重播、减少动画效果
└─ 高级：自定义结构、局部主题、原始参数
```

画布里的演示外框位置、复制、删除等编辑器设置可以折叠放在“编辑器布局”。不能把这个外框的高度称为打开后弹窗的固定高度。

“试用”应从明确的触发入口打开真实弹窗；“编辑内容”可以展示稳定的内容预览。弹窗出现后不把页面编辑选择操作混在用户点击按钮的手势中。现有打开路由捕获内容/主题的行为要说明：外部内容改变后重新打开查看，不把已打开浮层承诺为持续订阅编辑状态。

### 4.3 现有协议已经能表达普通说明弹窗

下面是**现有实验台可表达的组件节点片段**，不是建议新增的数据协议。它用一个按钮的动作打开弹窗；完整布局仍需放在原 modules 结构中。

```json
{
  "type": "GlassButton",
  "child": { "type": "Text", "text": "查看说明" },
  "onPressed": {
    "action": "dialog",
    "builder": {
      "type": "GlassDialog",
      "title": { "type": "Text", "text": "使用说明" },
      "content": { "type": "Text", "text": "这里是要显示的文字。" },
      "actions": [
        {
          "type": "GlassButton",
          "child": { "type": "Text", "text": "知道了" },
          "onPressed": "close"
        }
      ]
    }
  }
}
```

因此，第一阶段可以让用途表单写回现有节点，不必先引入全新的组件树或弹窗管理器。`showGlassDialog` 的专用演示模块可保留在开发模式；普通用户不必同时学习“按钮动作里的弹窗”和“打开弹窗函数模块”两条重复路径。〔W01、W04〕

### 4.4 弹窗内容候选应遵循任务规则

| 位置 | 普通模式可选 | 高级模式 | 不应在此直接出现 |
| --- | --- | --- | --- |
| 触发入口 | 按钮、图标按钮、文字链接、仅动作调用 | 自定义非嵌套交互的触发外观 | 局部主题、过滤分组、页面路由、弹窗自身 |
| 标题 | 文字、图标+文字、无标题 | 自定义标题布局 | 另一个弹窗/页面、整个菜单、主题类型 |
| 正文 | 文字、图文、表单、显式自定义 | 容器与布局树 | 主题/过滤策略作为“正文种类” |
| 操作区 | 按钮条目：文案、用途、结果、禁用 | 图标操作及自定义排列 | GlassToolbar 这类实现方式与“确认/取消”并列 |
| 目标对象 | 当前弹窗内容设计 | 查看目标节点配置 | 给固定目标再提供只有一个候选的类型下拉 |

这些是产品入口规则。库的 `Widget content` 仍可以接收任意合法 Flutter 组合，不能为了精简网站而收窄源库的通用 child 能力。

库的 `showGlassDialog` 本身也接收通用 WidgetBuilder；把普通弹窗目标固定为 GlassDialog 是网站为明确用途采用的约束，不代表源接口只能创建这一种节点。

## 5. 与 M3E Canvas 的组件能力逐项对照

M3E 的36种类型分在六类中，隐藏的三个类型通过属性或兼容数据到达。本表覆盖全部36种，但不把每个 M3E 类型都列为本项目必须开发的新 Glass 类。〔M01、M02〕

| fab、extendedFab | 玻璃按钮与图文 child 可组合，SDK 有悬浮按钮 | S+W：位置锚定、悬浮尺寸方案、滚动收起未接；统一运动契约有需求后再考虑 L |

| box | GlassSurface 可当材质容器 | W：给普通用户内容/布局模板；Stack、Padding 等通用布局未全面适配 |
| bottomSheet | 库无专门玻璃底部面板，SDK 可组合 | S+W；拖拽高度、关闭、键盘避让、统一外观若需复用再列 L |
| dialog | GlassDialog + showGlassDialog 有真实模态能力 | 当前基础强于仅放置弹窗外观；W：合并编辑入口、用途模板与结果映射 |
| snackbar | 库无专门玻璃消息条，SDK 有反馈组件 | S+W；消息、持续时间、动作与关闭可先用 SDK，玻璃外观再评估 L |

## 6. 布局差距：从演示模块到页面结构

### 6.1 两边现在实际表达的是什么

| 维度 | 当前实验台 | M3E Canvas | 建议 |
| --- | --- | --- | --- |
| 顶层对象 | 一张1200×1200演示画布，modules 保存 x/y/w/h | 多个 frames 屏幕 + groups/items | 先保留组件试用；需要页面流程时增加显式页面对象，P |
| 容器子关系 | props 里有真实嵌套节点，但主要靠递归参数表单编辑 | frames/groups 并列，按组中心点判屏幕归属，不是任意布局树 | 利用现有子树，补“添加到容器/移出/选中子项”，W；多屏归属宜用明确 ID |
| 元素选择 | 顶层模块选中；子节点主要在属性树中找 | 屏幕、单项、多选、组各有属性上下文 | 右侧固定对象名/用途/层级，W；多选与图层是 P |
| 编组 | GlassGroup 仅是渲染过滤机制；无等价画布多选编组 | 有顺序连接组与自由组，可锁定 | 编辑器编组单独命名和建模，P；不得复用 GlassGroup 表示它 |
| 排列 | Row/Column/Toolbar 的有限参数；无通用页面布局编辑 | 对齐、整理、磁吸连接、顺序/叠放管理 | 先补布局方向、间距、对齐、填充/内容自适应；自动整理后置 |
| 页面结构 | AppBar 散放在模块中，页面正文通过 builder 演示 | 屏幕尺寸、设备、滚动长度和栏位置 | 页面提供顶栏、正文、底部区；使用 SDK Scaffold 等组合，不先新增 GlassPage 容器 |
| 响应式 | 编辑器宽窄分支；组件仍受演示框约束 | 设备预设与重新布局，同名屏幕约定为变体 | 区分编辑器响应式与被设计页面响应式；显式定义断点/布局策略再实现 |
| 交互与编辑 | 内容可直接真交互，标题条拖动 | 编辑画布与独立预览分开 | 建立“编辑 / 运行”边界，预览状态可重置，W+P |

“容器里包含一个输入框”和“把两个独立模块拖到看起来重叠”不是同一种结构。应让拖入/加入容器时有明确高亮和层级结果；同时考虑空容器的最小可选区域、滚动区、长中文和焦点命中。

### 6.2 尺寸与布局的产品表达

普通模式优先提供“内容自适应、填满父容器、固定尺寸”三种意图，具体哪些控件支持由能力表决定。底层仍映射到已有 constraints、padding、width/height 或 SDK 布局组合。

按钮优先编辑内边距和最小触控区域；图标编辑图形尺寸；文字编辑字号/行高；弹窗编辑最大宽度和内容滚动；页面编辑视口与正文长度。这些不应统一成“所有类型都有同样的宽高”。

两边都没有完整通用响应式约束编辑器。M3E 的一次性整理/九宫格放置与本项目 Row/Column 的布局，不等于任意断点下都自动重排。第一阶段只承诺已定义的行列与尺寸规则，并写出中文长文案的可观察结果。

## 7. 动画效果差距

### 7.1 将四类动画分开看

| 动画层次 | 当前源库与实验台 | M3E Canvas | 差距判断 |
| --- | --- | --- | --- |
| 控件反馈 | 可点击卡片/按钮有 hover、focus、pressed、disabled；缩放/位移、着色和指针高光；主题提供时长/曲线 | CSS/Motion 的按压、波纹、菜单和控件变化 | 本库并非没有反馈；W：缺少直观状态试用与对照，不能只展示参数数值 |
| 材质变化 | AnimatedGlassSurface 插值材质，sigma直接用目标值；不自动循环 | 主题/形状/控件外观随状态变化；不同分支有各自过渡 | W：提供前后状态与重播；L：当前不把子内容替换、宽高变化统一做成自动布局动画 |
| 页面/弹窗 | 五种 GlassTransition；时长/曲线、页面反向时长；位移方向和幅度在实现里固定 | 七种页面过渡，四向滑入；标准/表现力方案，后者对适用过渡使用弹簧 | 若只需换曲线是 W；若要四向整屏、双页面联动或物理弹簧连续性则涉及 L |
| 编辑器与演示 | 拖拽、缩放是编辑行为；没有集中动效示意和动画时间轴 | 有动效方案示意，独立预览、部分导航展开与滚动收起 | 先做示意/重播/运行模式，W+P；不将编辑器运动冒充库效果 |

M3E 的动效方案示意使用一套弹簧参数，页面预览使用另一套；其属性面板并没有把所有质量/阻尼参数开放给普通用户。参考的是“用少量用途方案展示效果”，不是把更多物理参数塞进本实验台。〔M03〕

### 7.2 已有接口、未接入和真实缺口

| 项目 | 当前实现事实 | 后续责任 |
| --- | --- | --- |
| 常见动画时长与曲线 | GlassMotionSpec 已有 press/hover/release/surface 与页面曲线；构造参数可接收 Curve，网站仅列6种曲线 | W：命名为“轻柔/标准/快速”等预设并即时示意；额外已有曲线不必新增库 API |
| 动画试用 | 按钮需要实际悬停/按下；材质需要前后值；路由需要真正打开 | W：状态按钮、前后对比、重播；明确当前参数作用的动画类别 |
| 四向位移 | fadeSlide 固定从下方小幅进入；sharedAxis 固定水平位移并缩放，不能配置轴和方向 | L：有明确页面场景后扩展方向/位移配置；W 负责暴露，而非在 JSON 里保存无人消费的 direction |
| 双页面过渡 | 核心转场函数只接收单个 animation/child，未利用 secondaryAnimation 做离开页协同 | L：若要前后屏协同移动，需扩展实现和验收；不能把当前 sharedAxis 当成完整共享元素过渡 |
| 物理弹簧 | 当前是时长+曲线驱动；没有明确的弹簧初速度、阻尼、打断续接契约 | 先用现有 Curve 达成预设；真正需要连续物理运动时再立 L，不以近似曲线冒充等价实现 |
| 弹窗关闭时长 | spec 有 reverseDuration；showGlassDialog 目前只向 showGeneralDialog 传 duration，网站已不列独立反向时长 | L 候选：需要不对称开关时长才补消费链；否则保持界面不显示无效项 |
| 遮罩外观/动画 | 当前弹窗遮罩色固定为黑色0.32透明度，接口没有独立遮罩参数 | L 候选：业务证实需可配置后补；不要在网站提供伪透明度参数 |
| 共享元素、容器形变、拖拽跟手、滚动联动 | 没有这些完整可复用接口；材质插值不代表自动拥有它们 | 作为独立需求，P2及以后；必须明确目标元素与状态，不能统称“液态效果” |

### 7.3 保留已有性能与无障碍边界

继续遵守系统 disableAnimations/accessibleNavigation、主题 reduceMotion 和关闭动画的合并规则；动态开启也须停止位移/缩放，保留可见焦点。不得持续动画 blur sigma，不给每张卡片启动空闲 ticker；重叠区域不能错误共享 backdrop key。高对比度/减少透明度/低质量下仍应看清文字并操作。

建议每种预设都提供“正常 / 减少动画”并排演示，并用同一运行路径验证。M3E 的动效视觉与本库玻璃过滤开销不同，本次没有可比帧时间测量，不据画面丰富度宣称任一项目更流畅。〔F03—F05、M03〕

## 8. 整体流程差距

| 环节 | 当前实验台 | M3E Canvas | 下一步建议 |
| --- | --- | --- | --- |
| 明确任务 | 直接添加开发类型 | 按用途分类的组件材料 | 先选“要显示/输入/执行/导航什么”；使用模板，W |
| 建立页面 | 默认一张演示板 | 可创建命名屏幕和设备尺寸 | 若目标升级为界面设计，增加页面层与明确起始页，P |
| 修改内容 | 递归字段、下拉、复杂值 JSON | 按对象分派，按钮专用表单，其他类型有条件分支 | 内容/外观/行为分区；按上下文裁剪，不把普通任务送进 JSON，W |
| 理解影响范围 | 全局主题与局部包装节点并存，部分有继承提示 | 全局主题轴、当前对象属性、屏幕属性 | 固定显示“全局 / 此页面 / 此对象”；局部值可恢复继承，W |
| 建立联系 | 动作内嵌 builder，常见行为记录日志；变量仅覆盖有限用途 | 选择目标屏幕、画布连线、小地图、逐项动作 | 先做目标选择与结果显示，再做连线；不要把事件日志当成动作编辑器，W+P |
| 调试交互 | 编辑画布中运行真控件，运行状态与设计数据部分分离 | 独立预览栈、临时选择/值状态 | 增加运行入口、起始状态和重置；退出不改设计初值，W+P |
| 保存与恢复 | localStorage、JSON文本导入/导出、旧数据备份/恢复提示；无多工程管理 | JSON工程开/存、自动草稿，部分并发限制 | 保留已有保存失败提示；添加普通文件打开与工程版本说明，P |
| 交付 | 导出布局 JSON、下载整套实验台源码包 | JSON、单屏PNG、分享副本、实现提示词 | 先生成当前配置的 Flutter 示例或实现说明；图片和分享按需求加，P |

**下载源码的边界尤其要说明：** 当前 `playground-source.zip` 是实验台应用源码与快照，不是把用户当前 localStorage 中的设计自动生成成独立 Flutter 页面。布局 JSON 也是实验台协议，不是 Dart 源码。若用户目标是“画完直接开发”，这条交付链尚未完成。〔W05、W06〕

### 8.1 建议的完整最小操作链

1. 选择当前任务：组件试用，或页面设计。第一阶段可只完善组件试用，不必一次实现全部多屏功能。
2. 从用途入口添加一个模板，例如“文字说明弹窗”，给它可辨认的名称。
3. 在普通表单中改入口文案、标题、正文与关闭按钮；不展开原始类型。
4. 在“行为”里检查打开/关闭方式和返回结果；需要业务保存时明确交给消费应用。
5. 在“外观”选择尺寸/材质，在“动效”示意和重播；高级结构随时可查看。
6. 开启运行模式，用真实触发入口体验；运行时草稿、选择和返回值可观察、可重置。
7. 保存布局工程；需要开发交付时导出与当前设计一致的代码片段/依赖说明，或明确标注尚不支持。

这条链的第2—6步应优先完成，比先增加几十种底层节点更直接地解决本次反馈。

### 8.2 哪些 M3E 做法适合参考，哪些要修正后再借鉴

适合参考：用途分类、能力驱动的属性面板、逐项动作、屏幕/组件上下文、动效示意、独立预览、可编辑工程与静态/文本交付分开。

应吸取的边界：视觉容器不等于真实父子关系；按几何中心推断屏幕归属可能违背直觉；静态输入/日期/地图不应暗示真实业务；手写提示词覆盖后应提示已不随画布更新；分享必须一致处理所有层级素材。当前实验台已有保存状态和旧数据保护，不应为了模仿 M3E 而退回静默保存失败。

## 9. 真正需要补哪些接口

### 9.1 可先完成的网站工作，不以源库新增为前提

| 编号 | 改造项 | 使用已有能力 | 验收结果 |
| --- | --- | --- | --- |

### 10.1 三个必须能独立完成的用户任务

**任务A：点击文字看说明。** 建立文字链接入口，填写正文，点击试用，关闭后焦点回到入口；过程中不要求理解 GlassSurface、builder 或局部主题。

**任务B：确认一项操作。** 填标题/说明/两个按钮，取消与确认返回不同结果；不会因“确认”文案就自动执行删除数据。修改后保存重开，文案和结果约定保持。

**任务C：输入后返回结果。** 输入中文草稿，改一处外观不丢输入；取消不提交，确认可读到结果；退出运行后设计初值不被草稿替换。若需要密码/多行，必须等相应真实接口完成后才开放用途。

这三项通过后再考虑扩大内容材料数量。功能是否完成以“能完成任务”与对应接口消费链为准，不以属性项数量或可挂载类型数为准。

### 10.2 对应测试与兼容要求

- 分类与表单：普通/高级候选、固定类型不显示无意义下拉、真实命中、旧复杂节点能访问；自定义内容不会被模板覆盖。
- 布局与中文：320/390/820/1180/1500宽、100%/130%/200%字体、短窗口与软键盘；长中文按钮、深层选中路径、弹窗滚动；实际查看截图。
- 交互：鼠标、触摸、Tab/Enter/Space、Esc/外点、禁用、返回结果、重复打开；编辑与运行事件不串用。
- 动效：每种预设有触发条件与可观察效果；正反向、动态减少动画、无空闲ticker、无持续sigma插值；高对比度保持操作反馈。
- 数据：当前旧布局、JSON往返、类型与用途变更、撤销重做、控制器身份、存储失败、升级前备份；不清空浏览器数据来掩盖不兼容。
- 源库：遵循 `doc/AGENTS.md` 的格式/分析、行为、视觉与公开消费检查；必要物理IME、Android真机与性能单列，不能拿桌面截图代替。
- 网站：按 `deployment/agent.md` 和现有参考手册核对，实现、测试、发布分别记录。本文不改变上次发布连接阻塞的状态，也不重新执行发布。
