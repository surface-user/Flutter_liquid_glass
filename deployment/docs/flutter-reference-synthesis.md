## 2. 我们讨论的定位，应该转成哪些可检验要求

用户讨论的目标是：打开即有完整可用场景；保留增删和组合组件的自定义能力；真实展示Flutter接口及动效；可以保存/生成说明，未来按明确范围输出可使用成果；材质可选，场景中允许Flutter原生与库组件共存。

由此提出以下设计要求，均是建议而非已经实现：

1. 初始场景有明确任务和结果，例如切换内容、修改名称、确认操作；每个出现的组件都能说明在控制什么。
2. 场景预览使用真实Flutter组件和状态链。设计时选中/拖动不执行业务，运行时可真实交互，运行草稿不覆盖设计初值。
3. 每个参数有实际消费接口、触发条件和可见效果；不以能存进JSON代替有效支持。
4. 同时标清“本库能力”“Flutter SDK能力”“示例连接逻辑”。普通按钮/布局可以由SDK承担；本库聚焦可复用且有价值的交互、材质、主题与动效契约。
5. 保存布局、复制片段、生成提示词、下载实验台源码、导出当前场景工程，分别命名、分别验收。
6. 完整性用能力覆盖矩阵表达：用途、状态、参数、主题、键鼠、减少动画和降级、组合、结果与导出，而非组件总数。

### 3.1 这些优点也有明确使用前提

Appainter底部导航只更新选中索引、不切换body，Drawer里的Messages/Profile/Settings没有onTap；Buttons的空回调仍可用于观察Material状态外观。这适合主题工具的目的，却不足以证明完整业务场景。shadcn表单弹窗会pop返回表单值，但示例没有把结果消费到外层界面。fluent_ui则有取消结果回显，但复制片段与实际运行状态逻辑并非完全同一份。

我们应根据目标选择学习：外观对照可以采用有限空回调样例，完整场景必须实际连接内容/结果；不能把每种样例都强行当成完整场景，也不能让空回调示例承担“可直接使用”的承诺。依据：Appainter第5节/E19–E25；shadcn第5节/E22；fluent_ui第3/6节/E10。

## 4. 网站整体组织建议

首页先展示一个可用场景，同时给出场景选择。一个起步场景就足以形成主线，例如“轻量工作台”：侧栏导航→对应内容；工具栏按钮→确认/输入弹窗；确认结果→当前内容更新。扩展场景按要说明的能力增加，不为目录显得丰富先堆大量模板。

| 区域/入口 | 职责 | 与其它部分的关系 |
| --- | --- | --- |
| 场景选择 | 找到完整体验起点 | 标明场景涵盖哪些库接口、哪些为SDK组合 |
| 场景区域 | 设计与运行同一份内容，运行可重置 | 现有预览隔离可以保留，不额外复制一套假组件 |
| 左侧组件栏 | 自定义添加、删除、选择用途 | 添加导航/弹窗入口后，还能指定目标；对未连接状态给出清楚说明 |
| 参数区 | 当前对象的内容、行为、外观、相关动效 | 参数随对象和实际支持能力变化；材质是外观选择，表面/主题等包装不混入正文类型 |
| 接口说明 | 展示当前控件/场景的真实调用点、状态归属和最小代码 | 展示给所有需要查看的人，无需为了看代码强制切换复杂编辑模式 |
| 成果导出 | 保存设计或带走可用范围 | 各输出说明包含什么、缺什么以及接入方式 |

自由组合和场景体验可以共享组件栏、场景数据与运行器，避免形成两套越走越远的实现。“自定义”指用户改变场景，“接口查看”指开发者理解调用，二者不是同一个高级模式。是否调整现有入口，需用户后续批准实施。

## 5. 导航场景：从能点击到看懂关系

### 5.1 建议的一次体验

进入后看到“概览、收藏、设置”三个导航目的地，中央有对应内容。点击收藏后，选中外观变化，中央出现收藏内容。随后打开接口说明，看到一条具体链：

`点击收藏 → 回调交给场景 → 场景更新activePageId → selected传回各导航项 → 内容区域选择对应页面`

如果内容采用淡入，这段淡入标为“示例内容容器提供”；如果采用真实push新页，则标为“GlassPageRoute提供”。点击反馈、选中高亮、局部内容切换、路由转场分别展示，避免将一种效果全部归给导航项。

| 用户修改/操作 | 代码与状态归属（建议） | 应观察的结果 |
| --- | --- | --- |
| 文字/图标 | 导航项label/leading | 该入口内容变化 |
| 当前目的地 | 场景activePageId；各项selected由它派生 | 同一导航组仅对应项选中，中央显示匹配内容 |
| 目标内容 | 场景中稳定pageId的引用 | 点击后改变指定内容，不要求用户选择底层Flutter类型 |
| 禁用 | onPressed为空或对应可操作契约 | 鼠标/键盘不切换，禁用状态清晰 |
| 悬停反馈时长 | 对实际使用desktopControlStyle的导航项，跟随controlStyle/主题hoverDuration | 悬停/状态外观变化；不能宣称它改变了页面push时长 |
| 内容过渡 | 场景内容容器或GlassPageRoute，二者标明归属 | 可重放并观察内容/页面过渡 |
| 页面保留 | 场景规定保留或重新初始化 | 输入一段内容、切走再回来，行为与说明一致 |

### 5.2 四个导航相关组件分别干什么

本库当前源代码已说明：GlassNavigationItem是受控行；GlassTab是受控标签且关闭动作独立；GlassToolbar是Wrap操作容器；GlassAppBar是PreferredSizeWidget并组合SDK AppBar。它们没有共同承诺自动管理所有页面。

建议在场景里分别体现：导航项选目的地；标签管理已打开内容（增删/选中由场景管理）；工具栏操作当前内容；顶栏表达当前页面标题和页面操作。组件详情仍可单独研究样式，但至少提供一个“在场景中使用”的入口。

删除一个有连接的导航项时，应让用户看见其目标与影响；复制时创建新身份，撤销恢复连接。不要只保存屏幕坐标，留下无法解释的孤立入口。

## 6. 弹窗场景：内容、打开机制、结果和后续动作

### 6.1 建议的一次体验

在工作台点击“重命名”，弹窗显示当前名称。输入后确认，弹窗关闭，页面标题更新；取消则保持原值。旁边能查看本次返回值。说明弹窗、确认弹窗、输入弹窗是不同用途样例，可以共享已有开窗和内容组合机制。

`入口onPressed → showGlassDialog<T> → builder构建GlassDialog → 显示/聚焦/进入过渡 → 操作按钮校验并Navigator.pop(result) → 调用方消费Future结果 → 更新场景状态`

GlassDialog负责布局、表面与内容，showGlassDialog负责模态路由与过渡，场景负责解释返回结果和后续业务。取消/null、确认值、输入值不混成同一种“关闭”。输入校验和读取controller需要示例/适配器接好，不能仅因弹窗里放了输入框就宣称完整表单已实现。

| 编辑项/试用 | 真实接口或责任 | 验收观察 |
| --- | --- | --- |
| 标题、正文、按钮文字 | GlassDialog的title/content/actions；常用内容直接编辑 | 真实打开后的文本对应当前设计 |
| 说明/确认/输入用途 | 场景预设组合与返回契约 | 默认操作数量、返回值、后续反馈有区别 |
| 点击遮罩关闭 | showGlassDialog.barrierDismissible | 开启/关闭都实际点击验证，取消结果可解释 |
| 打开与退出效果 | motion.transition/curve/reverseCurve，具体时长看路由实际消费 | 开关减少动画后动态响应，关闭和重新打开不丢配置 |
| 弹窗宽度与内容自适应 | GlassDialog.constraints/主题dialogMaxWidth、布局内容 | 中文长文/窄屏滚动与动作可用，不混入入口按钮宽高 |
| 确认结果 | pop(result)→Future返回→场景更新 | 外层可见结果与实际状态一致 |
| 输入过程 | controller、校验、初值与运行草稿 | 空值/取消不提交，重开/重置按说明恢复 |

### 6.2 一个必须按消费点核查的现有细节

本库GlassMotionSpec含duration和reverseDuration；GlassPageRoute确实分别传给transitionDuration与reverseTransitionDuration。当前showGlassDialog调用showGeneralDialog只传spec.duration，没有单独转交spec.reverseDuration；buildGlassTransition会按动画方向选择curve/reverseCurve。

因此弹窗参数页不能仅根据GlassMotionSpec字段存在，就宣称“独立退出时长”已生效。这是本轮只读源码核查的新发现：**已确认参数消费差异，未作运行计时复现，也没有修代码。** 后续可选择网站先隐藏/解释该无效项，或另行批准源库补接口；需要把路由契约和测试补齐再宣称支持。

这个例子说明，参考库做得丰富仍需逐接口消费核验，不能把一个公共配置对象的全部字段机械暴露给每个组件。

## 7. 动效和材质应该怎样展示

每项动效说明四件事：发生条件、改变的属性、控制它的接口、关闭/降级后的行为。例如按钮按下的缩放来自交互层；导航选中颜色来自状态样式；页面推入来自路由；主题色变化来自主题层。默认先真实操作，再按需看时长/曲线；时间线和慢放等复杂工具不是第一步必需。

材质至少从用途上区分实色、半透明和玻璃等选择，具体选项以现有接口可表达范围为准。普通导航/工具栏可以直接组合SDK控件，主要动作保持可读；少量浮层使用玻璃表达层次。一个组件是否应进入库，看它是否提供稳定可复用的交互或视觉契约，不按是否有模糊效果判断价值。

本库已有GlassStyle、ButtonStyle/desktopControlStyle、GlassMotionSpec和glassReduceMotion，可先围绕这些已有能力组织场景。要提供完整通用实色组件体系，是否需新命名/接口是另一个库设计决策；本轮没有据此批准扩建。保留本库不持续动画模糊、动态系统减少动画、性能降级和高对比约束，不能因其它库允许动画blur就降低标准。

## 8. 导出：给用户什么，怎样证明能用

| 输出 | 建议承诺 | 必须包含/验证 | 当前实验台只读核查 |
| --- | --- | --- | --- |
| 保存布局JSON | 回到实验台继续编辑 | schema版本、节点身份、参数、连接、设计初值；往返与旧版本保留 | 当前保存按钮下载scene JSON；不是独立Flutter应用 |
| 生成提示词 | 告诉开发助手如何用指定库还原 | 库版本、真实API子集、布局、状态/事件/结果关系、材质/动效、SDK与自定义边界 | 已读导出路径未建立此能力证据；属于后续网站能力 |
| 复制最小代码 | 理解或接入一个具体用法 | import、状态、回调、必要宿主/主题及dispose；片段边界明确 | 不能由参数JSON自动推导“已有代码生成” |
| 下载实验台工程 | 得到实验台本身的源码 | 明确这是工具源码及其组件库快照 | 当前downloadProject指向静态playground-source.zip，构建脚本打包实验台源码；不是把当前自定义场景编译成工程 |
| 导出当前场景Flutter工程 | 接入或运行当前设计的受支持子集 | 依赖版本、入口、主题/资源、布局、状态连接、回调、必要组件源码引用；新目录构建/运行验证 | 当前核查路径没有此生成链；需要独立设计和验证，不能借现有源码下载按钮冒充 |

可先定义受支持场景的导出子集，再扩充。遇到无法生成的自定义节点要说明原因，保留JSON或提示词的交付途径；生成提示词不承诺模型必然还原，生成代码也要有构建证据。Appainter、Gallery及AppFlowy输出的对象不同，分别对照其实际调用链。

## 9. 网站适配、SDK组合、库接口与工程能力分开

| 事项 | 优先归属 | 判断依据 |
| --- | --- | --- |
| 场景入口、用途分组、中文参数解释、选中对象的上下文 | 网站适配 | 已有Widget能构造，缺少的是面向用户的组织 |
| 互斥导航状态、目标内容、Tab新增/关闭、弹窗结果写回页面 | 场景/网站状态组合 | 外部状态和回调本就是组件消费者职责；不要求每个控件变成应用框架 |
| 普通实色按钮、表单校验、标准布局/文本 | Flutter SDK组合 | 可以先按用途接入；是否进入库取决于重复且稳定的额外交互需求 |
| 每个组件参数消费矩阵、独立退出时长等确有接口差异 | 库侧核查候选 | 根据具体调用点判断，经过批准与回归后再补公开契约 |
| 工程导出、场景版本、资源/连接引用校验 | 网站工程能力 | 不应塞进纯UI库的绘制/主题层 |
| 系统减少动画、语义/焦点、低性能/无模糊下可读 | 库与网站各自负责 | 本库保证组件契约，网站保证宿主、编排和示例同样遵守 |

## 10. 建议的决策顺序与验收标准（未开始实施）

先确定一个能串起导航、内容、操作和弹窗的场景，再写清每个对象的职责和状态。随后给最重要的动效增加少量真实试用参数和接口说明，最后定义导出子集。大量组件、新通用导航框架、AI运行时和完整任意Flutter代码生成器可以在有明确需求时再评估。

| 要判断的问题 | 建议验收方式 |
| --- | --- |
| 场景是否完整 | 从入口做到结果，包含取消、禁用、重置；不依赖研究者解释每个孤立控件 |
| 导航是否建立关系 | 互斥选中、内容匹配、页内状态保留规则、删除目标后的引用、撤销恢复都有可观察断言 |
| 弹窗是否完整 | 内容来自当前配置，校验、返回值、外层结果、重复开关、焦点恢复和取消可验证 |
| 参数是否有效 | 修改参数后触发对应状态，以实际RenderBox/状态/动画采样断言；不只检查JSON变化 |
| 代码是否对应效果 | 展示代码与执行版本绑定；复制例子所需宿主和状态可获得；导出子集在干净目录构建 |
| 材质是否可选且可读 | 同场景比较实色/玻璃、浅深主题、高对比、减少透明、禁用/焦点、中文大字体 |
| 动效是否可靠 | 系统偏好在运行中改变仍响应；隐藏/卸载后无无意义ticker，性能另按设备实测 |
| 导出是否真实 | JSON往返保留关系；提示词列明接口和边界；工程输出可构建，未支持项不静默丢弃 |
